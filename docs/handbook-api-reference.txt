6.4 API contract A: events, registration and search
All routes are owned by Ananya; Anika consumes event routes, Aashi consumes browser routes. JSON
responses use UTC ISO timestamps, integer item IDs and stable snake-case keys. Validation failures are 422;
unknown IDs are 404; conflicts are 409; credentials missing/invalid are 401. Never return stack traces.

Registration multipart fields: event_id, category, color, location, optional brand, mark, private_mark,
plus photo. Canonical enumerations must match the vocabulary; category/color/location are required; trim strings
and cap notes at 500 characters. If the real item is outside the vocabulary, explicitly add and test a category
before registering it, or use an agreed “other” workflow with manual lookup.

device_id/kind. Equal → duplicate response; unequal → 409. Derive pending status from absence of an item,
avoiding a second state flag that can become inconsistent. The device key is supplied in X‐Device‐Key; it is
separate from staff credentials.

Map LookupError to 404 and decision conflicts to 409 at the route boundary; unexpected database errors
become a generic 500 with a server log. Use the same transaction approach for rejection, without changing item
status. Other pending claims may remain pending for staff review; the now-claimed item prevents their approval.
Explain this in the dashboard rather than silently treating them as approved or rejected.

approved audit entry and zero active-search results for that item. T est the same routes without staff credentials:
401 and no data mutation. A QR scan only opens an item reference; it never calls approve.

6.6 Images, authorization, privacy and CORS
Image path. Accept JPEG/PNG through UploadFile; install python‐multipart. Read at most 5 MiB plus one
byte and reject larger input with 413. Decode using Pillow, verify format and pixel dimensions (for example at
most 12 megapixels), reopen after verification, convert to RGB and re-encode to JPEG. Reject SVG, executable
content and files that only pretend to be images. MIME headers and filename extensions alone are insufficient.
Store under a generated UUID filename in a server-owned uploads directory outside the public static folder. Strip
metadata by re-encoding; retain no original filename in paths. Serve only through a route that checks item
visibility. On a failed database write remove the new file; perform a periodic orphan check. The photograph must
not disclose the hidden proof-of-ownership detail; crop or hide it before public display.

This is an integration pattern, not a standalone implementation: define require_staff and register_item
before adding it. Add optional fields from the contract to the final signature.
Staff authorization for local class demo. Use FastAPI’s HTTP Basic dependency (S13) with
username/password read from server environment variables. Reject missing configuration at startup, compare
using secrets.compare_digest, and return 401 with a Basic challenge when invalid. Staff enters credentials at
runtime; never hard-code them in JS, store them in localStorage or commit them. Keep all staff routes protected,
including registration and pending events. HTTP Basic must use HTTPS for any remote deployment; plaintext
LAN use is limited to disposable demo credentials on an isolated network.
CORS. Prefer serving frontend files from FastAPI at /ui so API calls are same-origin and need no CORS
exception. During split development, allow exactly http://localhost:5500 and the actual loopback variant in
CORSMiddleware, with required methods and Authorization/Content-Type headers. Do not combine wildcard
origins with credentialed requests. CORS is browser policy, not authentication.
Privacy choices. Collect only contact and ownership evidence needed for return. Proposed retention: delete
claim contact/evidence 30 days after closure, subject to college approval; preserve anonymized counts and
minimal audit reason. Do not publish real claims, databases, images, Wi-Fi passwords or API keys in Git. Backup
the database consistently with SQLite’s backup API, restrict file access and test restoration on a copy.
Security acceptance
Public search/detail responses contain no private mark, contact, staff password or audit evidence. A student
cannot approve by changing a hidden form field. Authorization and status transitions are checked on the server
every time.
